# tino's reproducible macOS + NixOS configuration

One flake-based, dendritic repository for:

| Host | Platform | Purpose |
|---|---|---|
| `MACOS-NIX` | Apple Silicon / `aarch64-darwin`, macOS 26.6 | nix-darwin + Home Manager + Homebrew GUI apps |
| `NIXOS` | Lenovo ThinkPad L14 Gen 1 Intel (20U1/20U2) / `x86_64-linux`, UEFI | NixOS + SDDM + MangoWC + DankMaterialShell |

The user is `tino` on both systems. NixOS uses `Europe/Berlin`, `de_DE.UTF-8`, a German keyboard, and DHCP.

> [!IMPORTANT]
> `hosts/NIXOS/hardware-configuration.nix` is a safety placeholder. Replace it with the file generated by the minimal NixOS installation before building `NIXOS`.
>
> A `flake.lock` is intentionally not checked in yet because Nix was not installed in the environment where this project was generated. Create it on the first bootstrapped machine, review it, commit it, and use that same lock file on both hosts.

## Why flakes and Home Manager?

### Flakes

`flake.nix` provides standard host outputs and `flake.lock` pins the complete dependency graph. Updates are explicit and reviewable. Pure evaluation also discourages undeclared dependencies.

Flakes remain officially experimental. They only include Git-tracked files when the source is a Git repository. Remember to `git add` new modules and the generated hardware file before building.

### Home Manager

Home Manager owns user packages and application configuration. It is integrated into NixOS and nix-darwin, so a single system rebuild activates both system and user generations. This avoids a second standalone Home Manager lifecycle.

Home Manager may refuse to replace existing files. This project configures `backupFileExtension = "hm-backup"`, so first activation can preserve a conflicting file as `*.hm-backup`.

## Why the dendritic layout?

Every `.nix` file under `modules/` is automatically imported as a top-level flake-parts module by `import-tree`. Features contribute deferred lower-level modules to:

- `dendritic.nixos.NIXOS`
- `dendritic.darwin."MACOS-NIX"`
- `dendritic.home.tino`

For example, `modules/ghostty.nix` owns shared Ghostty configuration, while `modules/macos-apps.nix` supplies the Darwin-only installation source. Files are organized by feature rather than by module class.

The central typed collections are declared in `modules/dendritic.nix`; `modules/outputs.nix` evaluates them into the two host outputs.

## macOS bootstrap (`MACOS-NIX`)

### 1. Install Apple's command-line tools

```bash
xcode-select --install
```

Wait for installation to finish.

### 2. Install official upstream Nix

Use the official multi-user installer:

```bash
curl --proto '=https' --tlsv1.2 -L https://nixos.org/nix/install | sh
```

Close and reopen Terminal when it finishes. Confirm:

```bash
nix --version
```

### 3. Clone this repository

Clone this repository:

```bash
git clone https://github.com/codingtino/nix.git ~/nix-config
cd ~/nix-config
```

If this is the first configured host, create the lock file without modifying global Nix settings:

```bash
nix --extra-experimental-features 'nix-command flakes' flake lock

git add flake.lock
git commit -m 'Lock Nix inputs'
git push
```

`flake.lock` is essential: do not independently create a different lock file on the second host.

### 4. Inspect the Darwin build

```bash
nix --extra-experimental-features 'nix-command flakes' \
  build '.#darwinConfigurations."MACOS-NIX".system'
```

This builds without activating.

### 5. Bootstrap nix-darwin

```bash
sudo nix --extra-experimental-features 'nix-command flakes' \
  run github:nix-darwin/nix-darwin/nix-darwin-26.05#darwin-rebuild -- \
  switch --flake '.#MACOS-NIX'
```

Open a new terminal. Future activations use:

```bash
cd ~/nix-config
sudo darwin-rebuild switch --flake '.#MACOS-NIX'
```

This also activates Home Manager and invokes Homebrew Bundle. `nix-homebrew.autoMigrate = true` allows an existing standard `/opt/homebrew` installation to be adopted.

### 6. Verify

```bash
scutil --get ComputerName
scutil --get LocalHostName
hx --health
herdr --version
brew bundle check
```

## Minimal NixOS installation on the ThinkPad L14

The intended workflow is deliberately two-stage: first create a bootable minimal NixOS system and its real hardware scan, then apply this repository.

### 1. Boot the stable minimal installer in UEFI mode

Download the NixOS 26.05 minimal ISO from <https://nixos.org/download/>. In the L14 firmware:

- boot the USB entry marked UEFI
- disable Secure Boot for this initial setup unless you separately configure a signed-boot solution
- keep storage controller mode compatible with Linux (normally AHCI)

Follow the official manual for partitioning because disk names and desired data layout must not be guessed here: <https://nixos.org/manual/nixos/stable/#sec-installation-manual>.

Mount the root filesystem at `/mnt` and the EFI System Partition at `/mnt/boot`, then generate configuration:

```bash
sudo nixos-generate-config --root /mnt
```

### 2. Make the temporary installation bootable and create `tino`

Edit `/mnt/etc/nixos/configuration.nix`. Keep its generated hardware import and ensure the temporary configuration contains at least:

```nix
{
  boot.loader.systemd-boot.enable = true;
  boot.loader.efi.canTouchEfiVariables = true;
  networking.networkmanager.enable = true;

  services.openssh = {
    enable = true;
    openFirewall = true;
    settings = {
      PermitRootLogin = "no";
      PasswordAuthentication = true;
      KbdInteractiveAuthentication = false;
    };
  };

  users.users.tino = {
    isNormalUser = true;
    extraGroups = [ "networkmanager" "wheel" ];
  };
}
```

Install and set the user password:

```bash
sudo nixos-install
sudo nixos-enter --root /mnt -c 'passwd tino'
reboot
```

### 3. Clone the locked repository

After booting the minimal installation, log in as `tino` and clone the repository. If Git is not installed yet:

```bash
nix --extra-experimental-features 'nix-command flakes' \
  shell github:NixOS/nixpkgs/nixos-26.05#git --command \
  git clone https://github.com/codingtino/nix.git ~/nix-config

cd ~/nix-config
```

### 4. Replace the hardware guard

```bash
sudo cp /etc/nixos/hardware-configuration.nix \
  ./hosts/NIXOS/hardware-configuration.nix
sudo chown "$USER:$(id -gn)" ./hosts/NIXOS/hardware-configuration.nix

git add hosts/NIXOS/hardware-configuration.nix
```

Review the diff. The generated file contains machine-specific filesystems, UUIDs, initrd modules, CPU/platform data, and swap devices:

```bash
git diff --cached -- hosts/NIXOS/hardware-configuration.nix
```

Commit and push it once verified:

```bash
git commit -m 'Add NIXOS L14 hardware configuration'
git push
```

### 5. Build before activating

```bash
sudo nixos-rebuild build --flake '.#NIXOS'
```

Validate the Mango configuration generated by Home Manager in the build only after activation is available; for later edits the direct command is:

```bash
mango -c ~/.config/mango/config.conf -p
```

### 6. Test and switch

```bash
sudo nixos-rebuild test --flake '.#NIXOS'
```

Check networking and the display-manager service before making it the boot default:

```bash
systemctl status NetworkManager
systemctl status sshd
systemctl status display-manager
```

If successful:

```bash
sudo nixos-rebuild switch --flake '.#NIXOS'
reboot
```

SDDM should offer and default to the `mango` session. DMS is bound to `mango-session.target`, so it should start only with MangoWC.

OpenSSH remains available after activation. Find the current address with `ip -br address` and connect as the normal user with `ssh tino@ADDRESS`. Root SSH login is disabled. Password authentication is enabled for bootstrap; after installing an SSH public key, set `services.openssh.settings.PasswordAuthentication = false` in `modules/networking.nix`.

## Routine operation

### Safe build/evaluation

```bash
# On macOS
nix build '.#darwinConfigurations."MACOS-NIX".system'

# On NixOS
nix build '.#nixosConfigurations.NIXOS.config.system.build.toplevel'

# Evaluate flake outputs and run declared checks
nix flake check --all-systems
```

The current repository could not be evaluated while generated because Nix installation on that Mac was explicitly disallowed. Run these checks after `flake.lock` exists and before activation. Any resulting compatibility fix should be committed for both hosts.

### Apply

```bash
# macOS
sudo darwin-rebuild switch --flake '.#MACOS-NIX'

# NixOS
sudo nixos-rebuild switch --flake '.#NIXOS'
```

### Update pinned Nix inputs

```bash
nix flake update
nix flake check --all-systems
```

Review `flake.lock`, build each host, then commit the lock-file update. Updating the lock file is separate from Homebrew application updates.

### Homebrew updates

Homebrew casks and formulae are declaratively present but are not Nix-store reproducible. Automatic updates/upgrades are intentionally disabled during activation. To update them explicitly:

```bash
brew update
brew upgrade
sudo darwin-rebuild switch --flake '.#MACOS-NIX'
```

`cleanup = "none"` prevents the first version of this project from deleting manually installed Homebrew items. Tighten this to `"check"` or `"uninstall"` only after Homebrew is fully represented in the repository.

### Rollback

NixOS retains generations in the UEFI boot menu. From a running system:

```bash
sudo nixos-rebuild switch --rollback
```

For nix-darwin:

```bash
sudo darwin-rebuild --rollback
```

Home Manager is integrated into these system generations.

## Adding and changing configuration

### Add a shared package

Add it to `modules/cli.nix` or create a dedicated feature file:

```nix
{ ... }:
{
  dendritic.home.tino = { pkgs, ... }: {
    home.packages = [ pkgs.ripgrep ];
  };
}
```

Because `import-tree` only sees Git-tracked flake files, stage it before testing:

```bash
git add modules/my-feature.nix
```

### Add a macOS application

Prefer sources in this order:

1. nixpkgs/Home Manager
2. Homebrew formula or cask
3. Mac App Store via `homebrew.masApps`
4. a pinned custom derivation

Add formulae/casks in `modules/macos-apps.nix`.

Mac App Store example (not active):

```nix
homebrew.masApps = {
  Xcode = 497799835;
};
```

MAS requires an authenticated App Store session, and removing an entry does not uninstall it.

### Add a NixOS-only feature

```nix
{ ... }:
{
  dendritic.nixos.NIXOS = {
    services.openssh.enable = true;
  };
}
```

### Add a cross-platform feature

A dendritic feature can colocate all relevant classes:

```nix
{ ... }:
{
  dendritic.nixos.NIXOS = { /* Linux system behavior */ };
  dendritic.darwin."MACOS-NIX" = { /* macOS system behavior */ };
  dendritic.home.tino = { /* shared user behavior */ };
}
```

## Reproducibility boundaries

Nix can pin package and module sources, but not all state on these systems:

- macOS itself and Apple system updates are outside nix-darwin.
- Homebrew casks/formulae converge to upstream's available artifacts and are not equivalent to Nix derivations.
- Mac App Store installation depends on an Apple ID and mutable store availability.
- DMS preferences changed through its UI are runtime user state unless later translated into managed files/options.
- Passwords, SSH keys, tokens, and other secrets are intentionally not managed yet.
- The generated L14 hardware file is machine-specific and must not be copied to another machine, including another L14, because storage UUIDs and devices can differ.
